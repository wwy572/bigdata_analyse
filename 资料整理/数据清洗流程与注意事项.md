# 数据分析中的数据清洗流程与注意事项

> 整理自 bigdata_analyse 项目学习笔记，以 OrderFromTmall part1（tmall_order_report.csv）为例，结合仓库内其他项目的实际清洗代码总结。

## 核心结论

- **清洗流程没有“固定模板”，但有一个固定的“检查骨架”。**
- 骨架里的每一步都要问一遍，但每一步**要不要做、怎么做**，取决于数据质量与分析目标。
- 仓库内各项目（AmoyJob、RentFromDanke、SZTcard、COVID-19 等）的清洗过程差异很大，正是因为数据和目标不同。

## 一、通用清洗骨架（7 步）

1. **加载 + 审查**：`read_csv()` 后先看 `head()` / `info()` / `describe()`，搞清楚形状、列名、类型、缺失量。
2. **列名规范化**：去空格、统一大小写、改名，保证后续引用不踩坑。
3. **重复值**：`duplicated()` 检查，**有全重复行才** `drop_duplicates()`；没有就直接跳过。
4. **缺失值**：`isnull().sum()`，然后**逐列判断缺失的业务含义**，再决定删除、填充还是保留。
5. **异常值**：检查是否有“脏数据”混入（如标题行混进数据列、负数金额、非法日期）。
6. **类型转换 + 文本/格式规范化**：日期转 `datetime`、数值去单位符号、文本去后缀、统一分类取值。
7. **（按需）派生字段**：如金额 = 单价 × 数量、楼层拆出所在楼层/总楼层等。

## 二、以 part1 为例的具体做法

数据集：`tmall_order_report.csv`，28010 行 7 列（订单编号、总金额、买家实际支付金额、收货地址、订单创建时间、订单付款时间、退款金额）。

- **审查**：`info()` 显示 `订单付款时间` 有约 3923 个空值——这是第一个关键点。
- **列名清洗**：`data.columns.str.strip()`，因为“收货地址 ”“订单付款时间 ”列名末尾有空格。
- **重复值**：`duplicated().count()` 结果为 0，**这一步直接跳过**。
- **缺失值**：只有付款时间为空，业务含义是“下了单但没付款”，**不能删**，后续按“未付款订单”参与计算（成交率、退款率都要区分）。
- **文本清洗**：`收货地址` 去掉“省/维吾尔自治区/壮族自治区/回族自治区”后缀，便于地图可视化匹配。
- **类型转换**：两列时间 `to_datetime()`，之后才能计算“下单到付款平均耗时”、按天/小时分组。
- **派生字段**：退款金额、实际支付金额直接使用，再计算成交率、退款率等指标。

## 三、注意事项（容易踩的坑）

- **“退款金额 = 0”不是缺失**，是业务上的“无退款”，不能 `fillna()`。
- **“付款时间为空”不是脏数据**，是“未付款”这一业务事实，不能当缺失删除。
- **缺失值处理必须结合业务**，不能机械地删或填。
- 每个字段在动手前都要先问：这个空值/特殊值在业务上意味着什么？

## 四、为什么其他项目的清洗不一样（仓库实例对照）

| 项目                         | 数据特点          | 主要清洗环节                                                                                         |
| ---------------------------- | ----------------- | ---------------------------------------------------------------------------------------------------- |
| AmoyJob（招聘）              | 文本不规范        | 缺失按业务填（人数填 1、“若干”当 3、年龄填“不限”）；正则格式化（中文数字转数字、工资区间取低值） |
| RentFromDanke（租房）        | 有脏行 + 复合文本 | 异常值清洗（“户型”列混入“户型”标题行并删除）；正则提取（楼层拆所在楼层/总楼层、地铁数、距离）    |
| SZTcard（深圳通）            | 半结构化 JSON     | 解析 JSON、只取需要的列、按日期过滤范围外数据、调整字段顺序                                          |
| AgeOfBarbarians（游戏）      | 多文件、字段多    | 多文件`concat` 合并、只挑分析需要的列以省内存                                                      |
| COVID-19                     | 多张宽表          | 多表合并/透视、`groupby` 按日期聚合                                                                |
| UserBehaviorFromTaobao_Batch | 数据量大          | 清洗下沉到 Hive SQL（`analyse.hql`），不在 pandas 中做                                             |

同样的骨架，但**每一步是否执行、怎么执行**，取决于数据质量 + 分析目标。

## 五、什么情况需要额外加步骤

| 情况                         | 需要加的环节                                       |
| ---------------------------- | -------------------------------------------------- |
| 多个文件/多张表              | 先统一列名、编码、主键，再`concat` 或 `merge`  |
| 缺失比例大、有业务含义       | 不要默认删，按列定策略（填充/保留/单独标记）       |
| 文本不规范（中英混、多余词） | 正则、标准化映射、分词                             |
| 数值带单位/混格式            | 统一单位、去掉符号后再转数值                       |
| 时间序列                     | 时区统一、排序、按日/时/月切分粒度                 |
| 要建模                       | 归一化、类别编码、异常值按统计法（3σ/箱线图）处理 |
| 文件很大                     | 分块读取、指定 dtype、抽样                         |
| 数据在数据库/Hive            | 清洗写成 SQL，不做 pandas 往返                     |

## 六、学习建议

1. **先把骨架背熟**：每次拿到新数据都按骨架过一遍。
2. **哪一步“检查结果是干净的”就跳过，哪一步有问题就深挖**。
3. part1 数据集很干净（无重复、无脏行），重点练习**缺失值的业务含义判断**和**时间/文本清洗**，适合入门。
